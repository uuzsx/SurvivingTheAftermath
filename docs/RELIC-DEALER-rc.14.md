# 劫后余生 rc.14：遗物商人生成修复

适用版本：1.20.1、1.21.1、1.21.2、26.1.1、26.1.2、26.2、26.3。

## 核对结论

- 七个版本均实际注册了 `surviving_the_aftermath:relic_dealer` 村民职业，并接入模组事件总线。它使用原版村民实体。
- 七个生产 JAR 都包含有效的 64×64 职业贴图，路径为 `assets/surviving_the_aftermath/textures/entity/villager/profession/relic_dealer.png`，与原版职业渲染层按注册名解析的路径一致。PNG 有 1925 个非透明像素；本轮未进行客户端画面验收。
- 修复了首次生成城市时创建通用结构部件的问题。通用部件不会调用城市的村民生成逻辑；现在新城市和存档重载均使用 `CityStructure.Piece`。
- 村民在出生方块中央生成，并检查实体碰撞，避免靠墙或隔壁方块导致卡住。

## 生成与交易规则

遗物商人由城市生成流程随机分配职业产生，仍不是每座城市必定拥有。它不会作为独立怪物在野外持续刷新。生成的遗物商人保留 1 点职业经验，防止立即失业；下界核心兑换附魔书的交易正常接入。

已有城市不会因更新自动补生村民。请在新存档或尚未生成的区块内检查。暂未添加专属工作站，因此普通村民转职、依靠工作站补货不在此次修复范围内。

## 验证方法与边界

修复前在 26.1.2 的新回归测试中复现：首次创建的城市是通用部件，跳过村民生成。保存了失败日志 `relic-baseline-26.1.2.log`。

新增两项服务端 GameTest：

1. 实际注册表查找遗物商人职业，按渲染路径加载 PNG，检查尺寸和非透明像素。
2. 使用主世界真实噪声生成器、种子 0、城市结构集候选和群系条件，调用生产代码创建城市及逐区块放置。测试世界为准备了地基的平坦场景；测试代码不直接召唤村民，也不指定其职业。检查随机生成出的遗物商人、出生碰撞、下界核心交易、结构存档重载，以及继续运行 240 tick 后仍存活并保留职业。

人口随机源采用固定样本，最多八次独立人口样本；不会修改生产代码的职业概率。该测试覆盖自然生成所调用的城市选择、部件创建、放置和人口生成代码，不等同于完整自然世界区块流水线或人工进服探索。

全部版本还运行现有副本、地形、结构避让、树叶清理、物品与附魔测试，以及六项客户端音频逻辑检查、数据生成和构建。基础环境未安装 KubeJS，其条件测试体会跳过；未进行图形客户端或多人联机实测。
